\section{Execution Context}    
Quando il codice JavaScript inizia la sua esecuzione, il JavaScript Engine crea un oggetto chiamato Global Execution
Context e lo mette in cima al Call Stack. L'Execution Context è un oggetto che contiene informazioni sul codice che deve essere eseguito, come ad esempio le variabili, le funzioni, e le variabili locali. Ogni volta che una funzione viene chiamata, il JavaScript Engine crea un nuovo Execution Context per quella funzione e lo mette in cima al Call Stack. Quando la funzione ritorna, il JavaScript Engine rimuove l'Execution Context dal Call Stack.
L'Execution Context è composto da due componenti principali: il Variable Environment e il Lexical Environment.
Il Variable Environment contiene le variabili dichiarate all'interno della funzione, le variabili dichiarate con la keyword var, e le dichiarazioni delle funzioni. Il Lexical Environment contiene le variabili dichiarate con la keyword let e const, e le variabili dichiarate all'interno di un blocco di codice.

\subsection{Hoisting}
Quando il JavaScript Engine crea un Execution Context, prima di eseguire il codice, esegue una fase di hoisting. Durante questa fase, il JavaScript Engine sposta tutte le dichiarazioni di variabili e funzioni all'inizio del codice. Questo significa che le variabili e le funzioni possono essere usate prima che siano state dichiarate. Tuttavia, solo le dichiarazioni vengono spostate all'inizio del codice, non le assegnazioni. Le assegnazioni rimangono al loro posto originale.
