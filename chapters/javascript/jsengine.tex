\section{JavaScript Engine}
Il JavaScript Engine è il cuore del JavaScript Runtime Environment, il componente che si occupa di eseguire il codice JavaScript.
Quando viene scritto del codice JavaScript, esso non viene esguito direttamente dall'hardware del computer,
ma passa attraverso il JavaScript Engine, che lo traduce in istruzioni che il computer può eseguire.
Questo processo avviene in tre fasi:
\begin{enumerate}
    \item \textbf{Parsing}: il codice sorgente viene analizzato e trasformato in un Abstract Syntax Tree (AST).
    \item \textbf{Compilazione}: l'AST viene tradotto in bytecode, che è un insieme di istruzioni che il computer può eseguire.
    \item \textbf{Esecuzione}: il bytecode viene eseguito dal motore JavaScript.
\end{enumerate}

Nella fase di parsing, il codice viene scomposto in token, che sono i blocchi di base del codice.
Dopo di che, i token vengono analizzati dal Syntax Parser, e trasformati in un Abstract Syntax Tree.

\subsection{Compilazione}
Nella fase di compilazione, l'AST viene tradotto in bytecode, oppure in linguaggio macchina, in base alle ottimizzazioni che il motore JavaScript decide di applicare. In questa sezinoe sono presentate le differenze tra interpreti e compilatori, e come il JavaScript Engine utilizza entrambe le tecniche per eseguire il codice JavaScript.

\paragraph{Interpreters e Compilers}
Esistono due macro-categorie di linguaggi di programmazione: quelli interpretati e quelli compilati.

Un linguaggio interpretato è un linguaggio il cui codice sorgente viene eseguito direttamente da un interprete.
L'interprete è il programma che legge il codice sorgente e lo esegue istruzione per istruzione.

Un linguaggio compilato è un linguaggio il cui codice sorgente viene tradotto in un linguaggio macchina, che può essere
eseguito direttamente dall'hardware del computer.
Il compilatore è il programma che traduce il codice sorgente in linguaggio macchina e, durante questa fase di
traduzione, effettua delle ottimizzazioni che rendono il codice più efficiente.

Ora resta da rispondere alla domanda: JavaScript è un linguaggio interpretato o compilato?
La risposta è: dipende dal JavaScript Engine che si sta utilizzando.
In generale si può dire che, quando è stato ideato da Brendan Eich nel 1995, JavaScript era un linguaggio puramente
interpretato, siccome il suo utilizzo principale era all'interno dei browser, e con la potenza di calcolo di allora non
ci si poteva permettere di aggiungere ulteriore tempo di attesa all'utente a causa della compilazione. Ma negli anni i
JavaScript Engine si sono evoluti, e oggi sono in grado di eseguire delle ottimizzazioni simili ad un linguaggio
compilato, che rendono il codice più efficiente.

Questo processo è chiamato Just-In-Time Compilation.

\paragraph{Just-In-Time Compilation}
Il Just-In-Time Compilation è una tecnica di ottimizzazione che consiste nel tradurre il codice sorgente in bytecode, e poi eseguirlo. Questo processo permette di eseguire delle ottimizzazioni che rendono il codice più efficiente.
In particolare, nella compilazione JIT, il codice viene tradotto in bytecode, e poi eseguito. Durante l'esecuzione, un
componente apposito, chiamato \textit{monitor}, monitora il codice, e se rileva che una parte del codice può beneficiare
di una ottimizzazione (ad esempio una porzione di codice che viene eseguita in più occasioni, o del codice che potrebbe
richiedere un elevato tempo computazionale), allora la traduce in linguaggio macchina, la ottimizza, e la sostituisce al
bytecode. Questo processo permette di eseguire il codice più velocemente, e di ottimizzare le prestazioni del programma.\\

\subsection{Esecuzione}
Come abbbiamo visto in precedenza, la compilazione e l'esecuzione del codice sono strettamente legate, e avvengono in
maniera simultanea. Il codice sorgente viene tradotto in bytecode, e poi eseguito dal motore JavaScript.
Ora vediamo nel dettaglio come avviene l'esecuzione del codice.
Innanzitutto è necessario presentare due concetti chiave: la Memory Heap e il Call Stack, che sono due componenti
fondamentali non solo di un JavaScript Engine, ma di qualsiasi motore di esecuzione di un linguaggio di programmazione.

\subsubsection{Memory Heap}
Il Memory Heap è lo spazio di memoria in cui vengono allocate le variabili e gli oggetti in JavaScript. Quando il codice viene eseguito, il motore JavaScript alloca spazio di memoria per le variabili e gli oggetti, e li memorizza nel Memory Heap. È una struttura di memoria non strutturata in cui gli oggetti vengono allocati in un modo relativamente disordinato, quando un oggetto non è più necessario, il motore JavaScript dealloca lo spazio di memoria occupato da quell'oggetto. Questo processo è chiamato garbage collection, e verrà discusso tra poco.

\subsubsection{Call Stack}
Il Call Stack è una struttura dati a pila che tiene traccia delle chiamate di funzione in un programma. Quando una funzione viene chiamata, il motore JavaScript aggiunge un frame di attivazione alla cima dello stack, e quando la funzione ritorna, il frame di attivazione viene rimosso dallo stack. Questo processo è chiamato \textit{push} e \textit{pop} dallo stack. Il Call Stack è una struttura dati a pila, il che significa che le chiamate di funzione vengono gestite in ordine LIFO (Last In, First Out), cioè l'ultima funzione chiamata è la prima a ritornare.
